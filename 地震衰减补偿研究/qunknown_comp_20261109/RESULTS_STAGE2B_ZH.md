## 事后诊断（看到结果后写的，只作描述；`scripts/diag_stage2b.py`、`logs/diag_stage2b.log`）

**深部窗口（1.0–1.75 s）的信噪比极低。** 方案里的 14 dB 是按整个道集的 Frobenius 范数定的，深部信号经过衰减后弱得多：

| 模型 | 5–30 Hz | 30–60 Hz | 60–90 Hz | 90–125 Hz |
|---|---|---|---|---|
| H1 | +7.3 dB | +6.2 dB | −10.9 dB | −13.8 dB |
| H2 | −9.7 dB | −12.1 dB | −29.4 dB | −32.2 dB |
| H3 | +7.3 dB | +8.3 dB | −14.1 dB | −16.3 dB |
| H4 | −4.7 dB | −6.1 dB | −18.1 dB | −20.4 dB |
| H5 | +2.2 dB | −0.4 dB | −21.8 dB | −23.3 dB |
| H6 | −3.2 dB | −4.1 dB | −19.8 dB | −28.1 dB |

**无噪声时流程是一致的**（m = 1）：IQ70 0.77–0.96，IQ30 0.91–0.99，VDB 0.89–0.94。加噪声后，IQ70 跌到 0.006–0.16，IQ30 0.16–0.62，VDB 0.26–0.77。

因此：
1. **这次检验实际测的是“噪声主导”的情形，不是“Q 不确定”的情形。** 70 dB 稳定项是在 Volve 半合成上选的，那里深部信噪比按实测资料标定；放到深部带内信噪比 −12 到 +8 dB、高频 −11 到 −32 dB 的数据上，70 dB 会把噪声放大到淹没信号。
2. **UQ-IQ 继承了这个缺陷。** 它的 s 取自 70 dB 增益上限，是常数，不随信噪比变化。UQ-IQ 比 IQ70 好得多，是因为不确定度带来的高切顺带压了噪声；而且 σ 越大越好（0.894 时 0.376），也说明这里需要的是更强的频带限制。真正适合这种情形的是带宽由数据决定的方法：VDB 的 Wiener 整形按局部谱确定带宽，C1 的稳定化更强。
3. **锚点的论证得到印证（描述）。** 锚点误取 0.9 s 时，不确定度被低估，结果几乎退回 IQ70（0.111 对 0.092）；锚点取 0（子波已知的位置）时为 0.313。
4. **Q 正确、无噪声时，UQ-IQ 的代价比半合成大。** UQ 为 0.71–0.92，IQ70 为 0.77–0.96，H2、H5 差 0.21–0.24；H6 例外（UQ 0.924，IQ70 0.772）。锚点在 0，整段 t* 都不确定，σ 0.447 带来的高切更狠。

## 这说明什么

- 阶段 2 的确认结论（胜过 IQ70、胜过“Q 取大”、与 VDB 持平）**只在深部信噪比合适的数据上成立**，还不能说不依赖生成器。这次检验把“生成器不同”和“信噪比状态不同”混在一起，分不开。
- 更根本的发现是：**UQ-IQ 只处理了 Q 的不确定度，没有处理噪声。** 设计稿原本写的是 H = S·E[G]*/(S·E|G|² + N)，N/S 由相干信噪比按时间、频率估计；实现时为了在 σ = 0 时与 70 dB 反 Q 逐位一致，把 N/S 换成了常数 s。在半合成上这没有问题，在噪声主导的数据上就是短板。
- 所以下一步应是把常数 s 换回由数据估计的 N(t, f)/S(t, f)，即设计原式。这同时也是 UQ-IQ 与 VDB 在原理上的结合：VDB 的长处正是由数据决定带宽。新算子要重新开发：先在半合成开发集和本批 FD 数据（现已用过）上开发，再在新数据上确认。

## 局限

- 只有 6 个模型；噪声实现与 fd2d 不同；m = 1 只是近似“Q 正确”。
- 14 dB 是全道集口径，没有像半合成那样按深部信噪比标定。按深部信噪比标定的 FD 检验没有做；若要做，需要另写方案、用新的噪声实现。
- 诊断是看到结果后写的，只作描述，不改变判定。
