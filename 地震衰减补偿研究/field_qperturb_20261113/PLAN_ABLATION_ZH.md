# 实测反转归因：时不变 / 时变整形消融方案（2026-11-18，开跑前提交）

**性质：**事后机制诊断，不是方法确认。Volve 这 8 组井已用于实验 9、13、本目录主试验和 `tie_lp.py`，是已见数据。本方案不改动 `PLAN_ZH.md` 的判定 R1–R5。

起因：外部审核（`REVIEW_HANDOFF_20261118_ZH.md`，任务 I2）。已排除的解释见 `uqw_improve_20261113/NOTE_ZH.md`：指标偏爱谱整形不能单独解释（第 2 节，半合成）；带外放大的影响 ≤ 0.007（第 3 节）。实测谱比不是常 Q 形状（第 4 节）。

## 1. 问题

Q 接近正确时（m = 0.85、1、1.2），UQ-W 的井震相关比 VDB 低 0.057（8 组平均，90% 区间 [−0.102, −0.012]；数字取自已归档的 `results/tie.json`）。VDB 由两部分组成：先只做 Kolsky 相位校正（PH），再做时变 Wiener 整形（窗长与 ε 为实验 12 选定的 B3 参数，`uqw_improve_20261113` 记为窗 0.5 s），目标是锚点窗的零相位统计子波 w_out。

要区分两种解释：
- **解释 B（静态）**：UQ-W 输出的谱形与 w_out 有一个与深度无关的偏差，例如实测震源子波、反射系数颜色，或与 T2 参考子波的差别。这种情况下，整条道用一个时不变滤波就能补上。
- **解释 A（随深度变化）**：偏差随深度变化，例如非常 Q 的散射使高频走平，必须逐深度整形。

## 2. 数据与输出

- 只读 `cache/out/IL_<L>.npz`（本机，git 忽略）中的 Input、UQW、VDB、IQ70，9 个 m。
- 只处理井轨迹用到的 inline（`tie.path` 的最近道和四邻道）。
- 除 PH 外不重算补偿。PH 是 VDB 的输入：`fdcheck.iq_t(D, cm, Q, None, m·c_sr, 0, TW)`，与 `confirmW.methods` 相同。

新增输出（参数全部在算任何井震相关之前固定）：

| 名称 | 定义 |
|---|---|
| UQW_TI | UQ-W 输出乘**一个**时不变零相位滤波 \|W_out\|·A/(A² + ε·max A²)。A 为整条剖面活道在 1.2–3.0 s 的平均振幅谱（按约 5 Hz 平滑），ε、w_out 与 VDB 相同 |
| UQW_TId | 同上，但 A 只取 2.0–3.0 s（时不变，但用深部谱估计） |
| UQW_TV | `lib12.tvw(UQW, w_out, ε, win)`，即 VDB 的时变整形接在 UQ-W 之后（等于 `uqw_improve` 中强度 1 的 UQWS） |
| PH | 只做相位校正 |
| PH_TI | PH 乘与 UQW_TI 同法的时不变滤波（从 VDB 一侧看：VDB 的时变性是否必要） |
| VDB_re | 用 PH 重建的 VDB，仅作一致性检查 |

## 3. 指标

- **T2（主）**：与 `tie.py` 完全相同，参考记录为测井反射系数 * Ricker(f_peak)。
- **T2-W（描述）**：参考记录换成反射系数 * w_out（该井第一条 inline 的 w_out，按 1 ms 重采样）。注意：w_out 正是 VDB 和各整形变体的目标子波，这个指标偏向整形后的输出，只用来看排名是否随参考子波改变，不作判定。
- **描述，不看井**：2.3–2.8 s 相邻活道相关的中位数（各井用到的 inline）。

## 4. 判定（只用 T2，m = 0.85、1、1.2，8 组平均）

记 Δ_base = UQW − VDB，Δ_TI = UQW_TI − VDB，Δ_TV = UQW_TV − VDB。差距缩小比例 r_X = 1 − Δ_X / Δ_base。

| 结论 | 条件 |
|---|---|
| 无法判定 | Δ_base 的 90% t 区间上限 ≥ 0 |
| **静态为主（解释 B）** | r_TI ≥ 0.6，且 Δ_TI 的 90% 区间上限 ≥ 0（时不变整形后不显著输给 VDB） |
| **随深度变化为主（解释 A）** | r_TI < 0.3，且 r_TV ≥ 0.6 |
| 混合 / 无法判定 | 其余情形 |

**描述（不判定）：**
- r_TId：时不变滤波改用深部谱估计后的差距缩小比例。如果 r_TI 小而 r_TId 大，说明偏差主要是浅深谱形不同，但在 0.5 s 储层窗内近似不变，倾向解释 A 的弱形式。
- PH_TI − VDB：若在 ±0.02 以内，说明 VDB 的时变性本身不是它占优的原因。
- Q 偏小（m = 0.5、0.6、0.7）和 Q 偏大（m = 1.4、1.7、2.0）两侧，以及 9 个 m 的平均，在两种参考记录下的同样差值。

**后续动作（事先写明）：**
- 解释 B：UQ-W 后接一个与深度无关的整形，作为候选，进入新数据（第六批半合成、FD H13 以后）的确认方案；不再开发时变 HAW，也不立项 N3。
- 解释 A：为 N3（本征吸收与散射分解）立项，仍须先在开发数据上写方案。
- 混合：报告各项数字，不立项。

## 5. 检查

- 用 Ricker 参考重算的 UQW、VDB、IQ70 的 T2 应与 `results/tie.json` 一致（最大差 < 1e-6）。
- VDB_re 与归档 VDB 的最大相对差 ≤ 1e-4（缓存为 float32）。
- 不一致时先查程序，修正写进补遗，判定规则不变。

## 6. 局限（事先说明）

- 井段只有 2.3–2.8 s（0.5 s）。时变与时不变整形在这么短的窗内本来就不易区分，所以设了 r_TId 作为中间档。
- 8 组井不独立。
- 这是已见数据上的事后诊断，结论只决定下一步做什么，不能当作确认。
- T2 只以 Ricker 为参考；T2-W 偏向整形后的输出。若要两者都不偏的参考，需另写方案。

## 7. 运行

在本机运行（需要 `cache/out` 和实验 13 的 `cache/inputs`）：
1. 冒烟测试：一条线、m = 1，只检查 VDB_re 一致和耗时，不保存结果；
2. 运行 `tie_ablation.py`（日志不打印分数）；
3. 运行 `analyze_ablation.py`，写 `analysis/ablation.json`，结果写进 `RESULTS_ABLATION_ZH.md`。

开跑前在 `PRE_RUN_HASHES_ABLATION.txt` 记录本方案和两个脚本的 SHA-256。
